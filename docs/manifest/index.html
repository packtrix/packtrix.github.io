Manifest reference

Manifest reference

Status: packtrix.io/v1alpha1, an alpha API. Fields and defaults may still change in later releases; the release notes say what changed.

Packtrix reads packtrix.yaml from the current directory by default. Use -f <file> to choose another file.

Minimal manifest 

apiVersion: packtrix.io/v1alpha1
kind: OfflineRepository
metadata:
  name: datacenter
spec:
  targets:
    - distro: ubuntu-24.04
    - distro: rocky-9
  packages: [curl, jq, nfs-common]

Everything else has a default.

Editor support

A JSON Schema of the manifest, schemas/v1alpha1/offlinerepository.json, lets editors complete fields and values, show what each field does and its default, and mark mistakes as you type. Editors that use the YAML language server, such as VS Code with Red Hat’s YAML extension, or Neovim, find it through a comment in the manifest:

# yaml-language-server: $schema=https://raw.githubusercontent.com/packtrix/packtrix/main/schemas/v1alpha1/offlinerepository.json

Other editors can map the schema to packtrix.yaml in their settings. The schema checks each field like packtrix validate, but not the rules across fields, such as unique target names or only naming an existing target: packtrix validate still has the last word. It is generated from the API types, with make update-schema.

Full structure 

apiVersion: packtrix.io/v1alpha1
kind: OfflineRepository
metadata:
  name: datacenter
spec:
  targets:                                   # which machines (required)
    - name: ubuntu-gpu                       # default: the distro name
      distro: ubuntu-24.04                   # built-in distro …
      architectures: [amd64, arm64]          # default: [amd64]
      extraRepos: []                         # … plus your own repositories
    - name: oracle-9
      repos: []                              # … or a distro defined from scratch

  packages: []                               # what the machines need (required)

  autoRepos:                                 # automatic vendor repositories
    enabled: true
    deny: []

  resolve:                                   # how dependencies are resolved
    baseline: minimal
    recommends: false
    alternatives: first
    exclude: []

  updates:                                   # how updates are picked up
    check: ""
    accept: all
    minAge: 0s
    publish: approval

  publish:                                   # where and how repositories are written
    path: ./repos
    signing: {}
    keepSnapshots: 3

  export:                                    # how bundles are written
    format: tar.zst
    splitSize: ""

spec.targets

A list of targets. A target is either a short form - distro: <name> or an object:

FieldTypeDefaultDescription
namestringvalue of distroUnique name. Used in only/except and in output paths.
distrostring or object—A built-in distro (see catalog). Exactly one of distro or repos is required.
architectureslist[amd64]Normalized names: amd64, arm64. Rendered as x86_64/aarch64 for RPM.
extraReposlist of repository[]Your repositories added on top of the distro, e.g. an internal repository.
reposlist of repository—The complete repository list for a distro Packtrix doesn’t know. Vendor repositories aren’t detected automatically for these targets.

distro as an object

Use the object form only to change a distro’s defaults:

distro:
  name: rocky-9
  components: [baseos, appstream, crb]
  mirror: https://nexus.internal/repository/
  auth: { … }
FieldDefaultDescription
name—Built-in distro name
componentsper distroParts of the distro to include. The same field works for every distro family. See components.
mirrorofficial serversFetch through a mirror or proxy (Nexus, Artifactory, a local mirror) instead of the official servers. Each repository keeps its path under the mirror, and its keys. With https://nexus.internal/repository/, Ubuntu’s https://archive.ubuntu.com/ubuntu/ becomes https://nexus.internal/repository/ubuntu/, its arm64 archive …/ubuntu-ports/, and Debian’s security archive …/debian-security/. packtrix render shows the resulting URLs.
auth—Credentials for distros that need them, e.g. RHEL subscription certificates

Repository object

Used in extraRepos and repos:

FieldRequiredDescription
nameyesUnique name
typeyesapt or rpm
urlyesBase URL. {arch} is replaced with the native architecture name.
suiteapt onlye.g. stable, noble, or / for a flat repository
componentsapt onlye.g. [main]. Not used for flat repositories.
gpgKeyyesPath to the repository’s public signing key
authnoCredentials (basic auth, bearer token, client certificate), as references to environment variables or files, never as literal values
extraRepos:
  - name: internal-tools
    type: apt
    url: https://pkgs.internal/apt
    suite: stable
    components: [main]
    gpgKey: keys/internal.gpg

Auth object

Used in distro.auth and in repository objects:

FieldDescription
username, passwordBasic authentication. Set both. password is a secret reference.
tokenBearer token, as a secret reference. Can’t be combined with password.
clientCert, clientKeyPaths to a TLS client certificate and its key. Set both.
entitlementDirectory holding RHEL subscription certificates, usually /etc/pki/entitlement

A secret reference is env:NAME (read an environment variable) or file:/path (read a file). Secrets themselves never appear in the manifest.

spec.packages

A list of packages, written once for all targets. An entry is either a string (the package name) or an object:

FieldDescription
namePackage name. When deb/rpm are set, it is only a label.
versionVersion constraint (see below). Also selects the repository for vendors that publish one repository per version, such as Kubernetes.
deb / rpmThe real package name for that format, when it differs
onlyInclude this package only for these targets. Values are target names, or deb/rpm for a whole format.
exceptInclude it for every target except these. Cannot be combined with only.
repoTake the package from this built-in vendor repository instead of the distro, e.g. nginx-org

Version constraints

ConstraintMatches
(none)Newest available
"1.34.1"Upstream version 1.34.1, any packaging revision
"1.34.*"Any 1.34.x
"1.34.1-1.1"That exact package version

Versions are compared with each format’s native rules (dpkg ordering for deb; rpm ordering, including epochs, for rpm).

Always quote versions. Unquoted, YAML reads 1.30 as the number 1.3. Packtrix rejects unquoted numeric versions rather than guess.

spec.autoRepos

FieldDefaultDescription
enabledtrueAdd built-in vendor repositories automatically when a package needs one. See auto-detection.
deny[]Repositories that must never be added automatically, as glob patterns, e.g. [epel-*]

spec.resolve

FieldDefaultDescription
baselineminimalminimal, none, or lock:<path>. See baseline.
recommendsfalseInclude APT Recommends and RPM weak dependencies
alternativesfirstFor APT a | b dependencies: first or all
exclude[]Packages that the machines get some other way, such as a driver installed by hand. They satisfy every dependency on them, at any version, and are never downloaded; plan lists the packages that need them. A package that is listed is still downloaded.

spec.updates

FieldDefaultDescription
check(empty: manual)Cron expression for update checks when Packtrix runs as a scheduled job
acceptallall, security (security updates only), or none (keep the lockfile pinned)
minAge0sWait this long after a new version is published before taking it, e.g. 72h
publishapprovalauto: publish after validation. approval: stop after plan until the lockfile change is approved.

spec.publish

FieldDefaultDescription
path./reposOutput directory. A relative path starts from the manifest’s directory. Machines are served from <path>/current.
signing.key—Reference to the private signing key, e.g. env:PACKTRIX_SIGNING_KEY or file:/path. Required to publish APT repositories.
keepSnapshots3Number of earlier snapshots kept next to the current one, for rollback. Their package files are hard links into the pool, so they take little space.

spec.export

FieldDefaultDescription
formattar.zstBundle format
splitSize(none)Split bundles into parts of this size, e.g. 4GiB for FAT32 media or transfer-system limits

Validation rules

packtrix validate and packtrix plan reject a manifest when:

  • it contains an unknown or duplicated field. A typo such as architecture: instead of architectures: is an error, never silently ignored;
  • a target has both distro and repos, or neither;
  • two targets have the same name;
  • only or except names an unknown target;
  • an entry has both only and except;
  • a target’s repositories disagree on distribution, release or format;
  • a listed package isn’t available for a target it applies to;
  • a package from a versioned vendor repository (e.g. Kubernetes) has no version;
  • a package matches several unrelated vendor repositories and has no repo.

Every error names the target, the package and what to change.
